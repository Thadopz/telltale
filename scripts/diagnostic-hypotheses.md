# 诊断假设与证据链

`agent.diagnostic_hypotheses` 默认开启。诊断使用请求内共享状态，子 Agent 和协调层通过 `record_diagnostic_hypotheses` 登记两个至四个竞争解释。显式关闭后，不提供动态或固定假设、假设控制提示及假设查询约束；开启时，用户诊断从实际观察生成候选。可信事故指定的 Prometheus、数据库必查项继续保留。RCAEval 对照实验可使用 `run --disable-diagnostic-hypotheses`。

每个候选包含唯一 ID、解释、服务、RFC3339 起止时间、真实证据编号及最多三个判别检查。检查记录工具名称、完整参数、预测方向及区分其他解释的理由。程序验证证据存在、服务和窗口匹配、工具实际已注册；模型提交的状态和反对证据会被重新计算。

数值预测使用 `increased`、`decreased`、`changed` 或 `unchanged`，与实际故障前后均值比较，变化判定容差为故障前绝对均值的 10%，零基线使用有限精度下限。日志、链路等辅助检查使用空 `metric` 和 `direction: observed`，仅记录查询覆盖，不据此证明原因。当前自动支持或反驳针对可比较的数值预测；辅助证据不会被任意转换为数值事实。

工具结果经过现有授权、脱敏和签名处理后进入共享状态，每次模型请求都会收到更新后的候选、观察、证据缺口和最近状态变化。获得初始比较观察后，外部调查查询必须匹配声明的检查参数；案例介绍、指标枚举及当前时间查询可以用于获取合法标识。未知引用、跨服务指标和错误窗口会被拒绝。

完成提交前，必须登记竞争解释并处理计划中的检查。实际预算、超时或权限缺口允许带不确定性结束。终止提交前先更新并保存最终假设，提交回执始终说明因果关系尚未被独立验证。某个预测被支持并不代表其完整因果解释得到证实；多个候选同时符合观察时，状态保持 `inconclusive`。

数值工具的适配结果使用现有 Evidence Envelope，观察格式为：

```json
{
  "kind": "metric_value",
  "subject": {"service": "example-service"},
  "scope": {
    "start_time": "2024-01-16T01:44:55Z",
    "end_time": "2024-01-16T02:04:55Z"
  },
  "fields": {
    "metric": "example-service_diskio",
    "before_mean": 0,
    "after_mean": 10
  }
}
```

此 JSON 仅说明接口格式。真实值必须从后端结果提取，不能从假设、模型说明或评测答案生成。没有匹配的时间、服务或有限数值时，不会生成可比较观察。普通 MCP 文本仍作为外部返回保存，不能自动成为数值证据。

共享状态最多保存 64 条比较观察和 32 条状态变化。模型快照优先保留当前检查所需的比较，展示最多 12 条观察和最近 6 条变化。会话状态保存候选、数值、证据引用及待检查项；上下文裁剪保留完整记录并说明省略，历史观察需要重新核对服务与时间窗口，不能直接恢复为本轮的新证据。

RCAEval 的项目工具使用 `baseline_change_v1`：在明确的任务时间窗口内比较数据，保留恒定基线之后发生变化的指标，并对结果进行数量限制。官方 BARO 函数和基线评分保持不变。比较观察由同一案例的实际 `get_metric` 结果提取，仍标注 `runtime_verified: false`，因为这些数据属于历史回放。

验证包括真实遥测候选检查、实际 MCP 签名结果回放、证据与范围校验、状态变化以及 SQLite 保存和上下文裁剪。留出题和回归题的模型结果需要分别报告，不能用状态机回放中的手工预测替代模型自行生成候选的成绩。
