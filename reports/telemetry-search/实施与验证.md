# 遥测搜索实施与验证

验证日期：2026-11-14。适配代码已实现；Prometheus、Loki、Tempo 尚未完成真实后端联调，当前结果不能作为生产观测效果证明。

## 工具契约

- `discover_telemetry`：逐服务检查当前用户、租户、Agent 权限，只公布已配置且获准访问的来源。来源显示 `not_probed`，不代表后端在线。保留诊断 HTTP 来源的真实能力及旧工具名称。
- `discover_metrics`：同样逐次核验来源、租户、服务、环境、实例与权限。`mode=names/labels/values` 分别发现指标名称、标签名称、指定标签值。使用 Prometheus `/api/v1/labels` 与 `/api/v1/label/<label>/values`，强制附加服务与环境的 `match[]`、显式时间和最多100项的 limit。可以用 `query.metric` 限定具体指标；结果截断时细化标签或时间。元数据中存在某个名称不能证明区间内实际存在样本。
- `query_metrics`：精确指标名称加范围标签，调用 Prometheus `/api/v1/query_range`。明确指定 RFC3339 时间和秒数步长，最多一天、100 条序列、2000 个点、后端响应 2 MiB。不会自动增大步长、计算均值或解析任意 PromQL。返回的是 step 求值点，可能遗漏采集点之间的尖峰。对照查询使用相同步长和标签、其他时间范围。
- `search_logs`：Loki `/loki/api/v1/query_range`，字段过滤仅为索引标签精确匹配，关键词使用大小写敏感的字面子串。不会假定 JSON 内容字段与索引标签等价。默认20条，最多100条片段，单次窗口最多一天。
- `search_traces`：Tempo `/api/search`，使用由类型化参数生成的 TraceQL，支持服务、实例、环境、操作、状态、最小及最大耗时。支持正常状态对照。搜索不提供游标，达到限制时须细化范围；采样和缺失 span 均为未知。
- `read_evidence`：重新验证引用及来源权限。日志读取原始行，支持同一 stream 时间戳前后各最多60秒，仍执行脱敏和模型输出预算。相同 stream、相同时间戳的多行会一起返回。链路引用读取 `/api/traces/<traceID>`，要求显式来源级 permission，以授权完整跨服务链路。后端 JSON 先完整脱敏，再通过标准 JSON 编码生成确定顺序的文本，按 Unicode 字符分页；默认512个字符，`page_runes` 支持64至2048。使用返回 `next_cursor` 作为下一次 reference，携带快照指纹与偏移；源数据变化明确失败。完整内容需要按顺序拼接文本分段后再进行 JSON 解码，单个分段不表示完整 span 或完整链路。后端读取上限32 MiB，超过时明确失败，不宣称可以读取无限大小链路。每页重新读取后端以校验快照，会增加后端读取开销；每轮共享调用及输出预算仍然适用。

旧 `analyze_log_window`、`read_log_evidence` 保留统计、基线和有限样本行为，原有进程内引用仍有旧限制。新增引用不依赖这些引用。当前告警不再按 alertname 合并不同实例，返回 matched、returned、truncated。

## 隔离、引用与分页

每次解析来源都要求配置 tenant 与当前 principal 的 tenant 一致，服务必须出现在来源 services 中，环境必须一致，并检查模态权限、来源权限、服务权限和 observability_agent 范围。指标和日志强制注入配置映射的服务与环境标签；冲突标签直接失败。实例限定通过配置映射执行。

引用使用标准库 AES-256-GCM 认证加密，绑定用户、租户、client_id 会话、完整来源配置指纹和十分钟过期时间。定位信息包含查询和可选 trace ID，不包含日志原文、URL 凭据或 bearer。每次读取重新鉴权，配置变化使旧引用失效。多实例和重启需要共享环境密钥 `TELLTALE_TELEMETRY_KEY`，值为32个随机字节的标准 base64；没有默认密钥，缺失时日志及链路查询明确失败。密钥轮换使旧引用失效。

Loki 没有直接使用的稳定原生游标。实现读取最多5000条的有界快照，按时间戳、完整条目稳定排序，使用加密游标携带查询、偏移和内容指纹。翻页重新获取并验证快照，无需持久化敏感原文。包含同一时间戳的记录不会通过递增时间戳跳过。快照变化时明确失败，要求重新查询；达到5000条时匹配总数未知、标记截断，必须缩小时间范围。后端有序返回不能保证5000条之外的稳定性，因此不会宣称已经遍历全部匹配。

游标绑定原查询，允许缩小页面 limit。共享调查预算仍限制每轮最多8个不同日志/遥测查询，阻止完全重复；翻页、其他窗口、不同步长产生不同查询标识。总工具返回预算由现有包装器保留。输出保护只豁免通过本地认证、当前重新鉴权成功的引用，其他内容继续脱敏。模型预算不足时整页记录不交付，保留范围与当前页面 retry_cursor，避免返回后续页面游标而跳过未交付记录；缩小 limit 后重试。极小预算连元数据也无法容纳时返回明确错误，不宣称成功。

Tempo 同样保留 retry_cursor；输出超限后可减小 page_runes 从当前偏移重试。重复保护使用来源查询、trace ID、偏移及页面大小，不能通过重新加密引用绕过相同读取限制。分页前完整处理敏感字段，避免跨分段的敏感值绕过脱敏。

## 配置与调用

配置示例：`manifest/config/telemetry.example.yaml`，将其中 sources 合并到实际 `tools.telemetry`，配置真实标签和租户。Tempo 使用标准属性 `resource.service.name`、`resource.service.instance.id`、`resource.deployment.environment`。来源级链路 permission 必须在权限角色中单独授予。后端认证从指定的 bearer_env 环境变量读取；不修改现有本地密钥配置。工具注册不会自动启用示例来源。

调用顺序：发现授权来源，然后选择真实 source/environment/service。示例中的 inventory 和时间范围为调用参数说明，不代表已经查询到这些遥测记录。

先发现指标名称；将 mode 改为 labels 发现标签名称，或使用 values 并提供 label 发现标签值：

```json
{"mode":"names","query":{"source":"metrics_prod","environment":"production","service":"inventory","start":"2026-11-14T00:00:00Z","end":"2026-11-14T00:10:00Z","limit":20}}
```

链路分段读取和继续读取均使用：

```json
{"reference":"初始 evidence_ref 或返回的 next_cursor","page_runes":512}
```

```json
{"source":"metrics_prod","environment":"production","service":"inventory","metric":"http_requests_total","start":"2026-11-14T00:00:00Z","end":"2026-11-14T00:10:00Z","step_seconds":15,"limit":10}
```

```json
{"source":"logs_prod","environment":"production","service":"inventory","keyword":"timeout","start":"2026-11-14T00:00:00Z","end":"2026-11-14T00:10:00Z","limit":5}
```

翻页使用相同参数加 `cursor`；读取使用 `{"reference":"返回的 evidence_ref","context_seconds":30}`。

```json
{"source":"traces_prod","environment":"production","service":"inventory","operation":"GET /inventory","status":"error","min_duration_ms":100,"start":"2026-11-14T00:00:00Z","end":"2026-11-14T00:10:00Z","limit":5}
```

统一结果继续使用现有 evidence envelope。data.telemetry 包含范围、后端、查询状态、表示方式、匹配数或 unknown、返回数、截断及原因、预算、查询标识和适用游标。data.records 为原始值、片段或后端链路数据。错误通过现有 error envelope 返回，不能解释为空数据。
